## Why

The generated repository is already canonical, but the installable template package, maintenance CLI, documentation, skills, tests, and synchronization code still retain the superseded subject-card, `CUS`, queue, reverse-map, functional-gap, manual-cleanup, and related multi-authority contours. This hybrid surface permits removed workflows to reappear and makes a green template check compatible with stale packaged code.

## What Changes

- **BREAKING** Remove every legacy runtime module, command, route, script, skill, active document, test, schema, and packaged asset named by the scoped forbidden-authority inventories.
- **BREAKING** Retire the old `CUS` customization registry, subject cards, functional gaps, reverse map, queue, parallel-research, manual-cleanup, old dashboard, and compatibility-reader contracts instead of preserving dormant adapters.
- Make the installable `one-c-autoresearch` runtime and workspace surfaces match the canonical generated repository.
- Keep the small template-maintenance surface for generation, synchronization, packaging, and `checks template|doctor|research` in existing repository-local scripts outside the installable project runtime.
- Publish `research-template.zip` as a separate release artifact rather than package data inside `one_c_autoresearch`.
- Release the breaking canonical package as `0.3.0`; `0.2.0` is the exact last compatible legacy package version.
- Make synchronization replace the owned package surface and fail on unexpected stale files instead of copying over an open-ended destination while preserving old `cli.py`, `doctor.py`, and modules.
- Update repository maps, verification instructions, package contents, and tests so absence of forbidden authorities is a release gate.
- Preserve current canonical source routing, stable DIF identity and lineage, semantic/physical difference closure, platform-safe CSV field limits, DIF classification, MRQ consolidation, target decisions, invocation inspection, source import, and immutable-generation behavior.
